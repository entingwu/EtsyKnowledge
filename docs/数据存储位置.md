# 导入数据存储位置

导入服务（8000）和查询服务（8001）从 `~/PycharmProjects/knowledge_base` 启动，但 Milvus 和 MinIO 用的是 EtsyKnowledge 的 `etsy-kb-*` 容器，所以数据文件落在 **`~/PycharmProjects/EtsyKnowledge/volumes/`** 下。

## 1. Milvus：文字切片和向量（检索时查这里）

- 容器：`etsy-kb-milvus`，地址 `127.0.0.1:19530`
- 两个 collection：
  - `kb_chunks`：每份 PDF 切出来的文本块（含图片摘要），带 BGE-M3 向量和 `file_title` 等字段
  - `kb_item_names`：商品名索引，每份文件一条
- 磁盘位置：`~/PycharmProjects/EtsyKnowledge/volumes/milvus`（2026-10-14 约 294MB）
- 网页查看：Attu http://127.0.0.1:8080
- 重复导入同一份文件：两个 collection 都会先按 `file_title` 删旧数据再插入，不会重复

## 2. MinIO：图片和原文件

- 容器：`etsy-kb-minio`，API `127.0.0.1:9000`，控制台 http://127.0.0.1:9001
- bucket `knowledge-base`：
  - `upload-images/`：PDF 里的图片。MD 和切片里的图片链接都指向这里，例如 `http://127.0.0.1:9000/knowledge-base/upload-images/011_…`
  - `pdf_files/日期/`：上传的原始 PDF
- 磁盘位置：`~/PycharmProjects/EtsyKnowledge/volumes/minio`（2026-10-14 约 84MB）

## 3. 本地中间文件（排查问题用，检索用不到）

- `~/PycharmProjects/knowledge_base/data/<日期>/<task_id>/<文件名>/`
- 里面有 PDF 转出的 MD、本地图片，以及带图片摘要和 MinIO 链接的 `*_new.md`
- 确认导入没问题后可以删

## 4. 配置注意

- 服务读的是 **`knowledge_base/.env`**（`atguigu/config/config.py` 固定读项目根目录的 `.env`），不是 `EtsyKnowledge/.env`。改模型、地址都要改这个文件，改完重启对应服务
- 当前 `VL_MODEL=qwen3-vl-plus`。`qwen3-vl-flash` 在公共 endpoint `dashscope.aliyuncs.com` 上会返回 404 Model not exist，图片摘要会全部失败
